查询英雄联盟“海克斯大乱斗”中每个英雄的海克斯胜率排名与推荐出装。

网站：https://wangyuanpei8-del.github.io/WypHex-aram-site/

## 使用

- 搜索英雄中文名、称号、外号或英文名，选择英雄查看详情。
- 海克斯按已收录的该英雄搭配胜率降序，每个稀有度筛选最多显示前 20 个；不足 20 个时显示实际数量及缺项提示。可筛选棱彩、黄金和白银。
- **鼠标停在海克斯图标或名称文字上**时立即显示效果浮层，移出该图标或名称立即隐藏，无等待或淡入动画；排名、胜率、场次和名称旁空白不触发。浮层显示名称、稀有度、效果说明和版本核对信息，自动避让窗口边缘，并跟随浅色或深色主题。
- 键盘 Tab 聚焦名称可查看说明，Esc 关闭。手机点击名称展开，再次点击或点外部关闭；滚动、筛选或切换英雄时也会关闭。
- 推荐出装展示胜率与场次。少于 1000 场的样本标橙色，仅供参考。
- 手机上选择英雄后进入全屏详情，点击“返回”回到列表。

## 数据与正确性

**胜率、出装和海克斯效果描述均来自 [Hexdata（hexdata.com.cn）](https://hexdata.com.cn/)**。效果说明提取自海克斯详情页“适合英雄和出装思路”中的效果段落，保留来源文字和数值，不混入其他网站的描述，也不把推荐英雄、阵容建议或统计数字当作效果。浮层不再重复显示数据来源，统一来源说明保留在页脚。

暂未读取到的效果明确显示“Hexdata 的效果描述暂未收录”，可前往 Hexdata 原站核对；自动更新会优先补齐缺项，并分批核对已有描述的来源版本和日期。浮层区分“已核对”“版本待核对”“旧版描述”和“描述待补齐”；只有来源页的版本与当前榜单相同才标记为已核对。页面结构不匹配或获取失败时保留已有 Hexdata 描述，不猜测内容。

英雄的海克斯排名只使用该英雄页面的搭配数据，按胜率降序排列，不再拼入其他详情页的零散搭配。尚未同步可见表时明确标注摘要状态。统计是公开对局样本，并非全服所有对局；跨版本和低样本结果应谨慎比较。网页将来源客户端版本号（例如 16.22）换算为游戏显示版本号（26.22）。

名称、图标使用游戏资源，图标通过 CommunityDragon 等资源接口下载；图标资源来源与效果描述来源分别处理。本站为非官方工具，与 Riot Games 无关联。

## 更新与发布

`.github/workflows/update.yml` 每小时运行，也支持在 GitHub Actions 中手动执行“自动更新”（勾选 `descriptions` 可只补齐和核对描述）：

1. `fetch-hexdata.mjs` 抓取英雄榜、海克斯榜和最多 30 个详情页，保存到 `data/open/hexdata.json`。优先补齐缺少稀有度或效果描述的海克斯，再更新过时的英雄及海克斯搭配。
2. `build-data.mjs` 生成胜率与出装数据；`build-augment-descriptions.mjs` 从缓存生成描述及对应来源链接，无需再访问其他描述数据源。
3. 数据有变化时补齐图标并提交，随后生成单文件版，上传到该次运行的 Artifacts（保留 90 天）。

为尊重 Hexdata 的访问限制，详情页之间间隔 2 秒，遇到限流停止，留待下次继续。缺项和过期数据会分批补齐；顶栏显示英雄榜单日期；英雄详情分别显示来源详情日期和合并搭配数据的日期范围。较早数据、日期未知的数据会明确标记，出装显示该英雄详情日期，不会用榜单日期冒充详情日期。

GitHub Pages 发布 `main` 分支。修改推送后，在 Actions 中确认 `pages build and deployment` 成功。更改交互或样式时，同时更新 `index.html` 的静态资源版本参数，避免浏览器使用旧缓存。

## 本地开发

使用 Node.js 20+，不需要安装前端依赖：

```sh
node --test
node scripts/build-data.mjs
node scripts/build-augment-descriptions.mjs
node scripts/build-standalone.mjs
```

双击 `index.html` 或启动静态服务器预览。单文件版位于 `dist/hexaram.html`，内嵌网页、数据、描述和图标，可离线打开；`dist/` 不提交到仓库。线上更新不会修改已经下载的旧 HTML 文件。

描述解析会检查未展开变量、残留标签和混入的推荐段落；不合格内容不会覆盖缓存。抓取记录来源页本身的版本和数据日期，而非本机抓取日期。更新脚本会轮换重试缺项，同时保留英雄统计更新名额。

本次核对快照：Hexdata 数据日期 `2026-11-09`、游戏版本 `26.22`，222/222 个海克斯效果已收录并核对来源版本与日期。后续状态由自动流程持续更新，以页面当前信息为准。

覆盖范围：静态英雄页只显示精选摘要；正常浏览器页面还提供“英雄海克斯表现”可见表。项目以该可见表为准，读取全部公开展示的行，再按胜率降序显示最多 20 个；例如来源亚索表有 16 条，就展示 16 条。不会用其他海克斯详情页的零散搭配补入已同步的可见表，也不会用摘要覆盖它。数据接口不提供批量访问，不直接读取或绕过登录限制。

README 的功能说明仍由人工维护；“更新记录”标记块自动维护。项目提交后自动记录项目更新时间，数据任务写入变更时自动记录数据写入时间，统一使用 UTC+9。无数据变化的定时检查不会制造新的数据更新时间。

## 可见表同步

`.github/workflows/visible-tables.yml` 每小时以最多 20 位英雄为一批同步普通浏览器可见的表格，优先补齐未同步或过期的英雄；代码提交不会触发整站重复抓取。解析器同时支持原生表格和页面可见文字布局，检查来源标题、版本、日期、显示条目数与实际解析数；不完整或不匹配时保留缓存。遇到访问限制或连续三次加载失败会停止，保留本批成功数据，留待后续批次继续。只读取未登录时实际展示的内容，不读取隐藏数据或私有接口。

可手动运行“同步英雄可见搭配表”，设置本批英雄数。普通 HTML 摘要抓取仍负责榜单、描述和出装；已同步可见表的海克斯搭配会保留独立日期，避免被精选摘要覆盖。`scripts/import-hero-table.mjs` 也支持导入保存的渲染后 HTML。

可见表同步进度显示在顶部自动更新区块，完整性按页面声明的总条数检查；页面加载中的 0 条、未完整读取的行和重复海克斯都不能覆盖缓存。
